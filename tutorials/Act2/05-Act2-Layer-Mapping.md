# 05 — Layer Mapping: Four Layers, Two Engines

HCMD has four layers:

1. **Meaning**  
2. **STS**  
3. **PSC**  
4. **Implementation**

Act 1 demonstrated these layers in motion.  
Act 2 explains how they map onto the Two‑Copilot Model.

The mapping is not arbitrary.  
It is the structural alignment that makes the loop reproducible.

---

## Meaning → Copilot App

Meaning is ambiguous, human‑anchored, and interpretive.  
It requires dialogue, refinement, and negotiation.

Only the meaning‑side engine can operate here because:

- ambiguity is allowed  
- intent must be clarified  
- tasks must be interpreted  
- refinement is iterative  

Meaning cannot be processed by the structure‑side engine without collapse.

---

## Skills (Huts) inside the Meaning Layer

As meaning stabilizes, certain ideas begin to cluster into **Skills (Huts)**:

- reusable semantic units  
- refined during STS development  
- independent of language or implementation  
- stable across projects  

Skills belong entirely to the Meaning‑Side Engine.  
They do **not** cross the boundary as semantic units.  
They cross **only** after the STS is complete, and only as **structural units** in the PSC.

---

## STS → Copilot App

The STS is the final artifact produced on the meaning side.  
It is deterministic, complete, and implementation‑free.

The STS belongs above the boundary because:

- it emerges from meaning  
- it resolves ambiguity  
- it expresses intent without structure  
- it is the hinge between the engines  

Once the STS is complete, meaning ends and structure begins.

---

## PSC → GitHub Copilot

The PSC is the first artifact produced on the structure side.  
It defines how the implementation will be organized.

The PSC belongs below the boundary because:

- it is structural, not semantic  
- it depends on conventions, not interpretation  
- it prepares the implementation  
- it must be deterministic  

Skills appear here **only** in structural form:

- Skill → PSC component  
- Skill cluster → PSC grouping  
- Skill relationships → structural dependencies  

The PSC cannot appear in the meaning layer without contaminating intent.

---

## Implementation → GitHub Copilot

Implementation is the final layer.  
It is mechanical, reproducible, and convention‑driven.

The structure‑side engine generates:

- code  
- files  
- project layout  
- deterministic outputs  

Implementation cannot rise above the boundary without biasing meaning.

---

## Why this mapping works

The mapping aligns each layer with the engine that is cognitively suited to it:

- **Meaning + STS** → interpretive engine  
- **PSC + Implementation** → structural engine  

This alignment is what makes HCMD:

- stable  
- reproducible  
- scalable  
- deterministic  

The loop works because each layer is handled by the engine designed for it.
