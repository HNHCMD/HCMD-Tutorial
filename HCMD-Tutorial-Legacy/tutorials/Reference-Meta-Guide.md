# **HCMD Meta Guide**  
*A structural guide to reading and performing HCMD tutorials*

---

## **1. Purpose of This Document**

This document explains how to read HCMD tutorials, how to interpret their artifacts, and how to perform the HCMD loop. It is a conceptual reference for the entire tutorial system. It is not part of any specific Act.

HCMD tutorials are not solution manuals. They are demonstrations of disciplined refinement. The reader is expected to perform the loop, not merely observe it.

---

## **2. What an HCMD Tutorial Is**

An HCMD tutorial is a **performed sequence of refinements**.  
It demonstrates how a problem is clarified, structured, and implemented through the HCMD loop.

An HCMD tutorial:

- begins with an initial task  
- produces an initial, imperfect answer  
- refines the structure  
- clarifies the task  
- improves the implementation  
- documents the reasoning  
- converges toward a minimal, coherent solution  

The tutorial is not a recipe.  
It is a record of disciplined thinking.

---

## **3. The HCMD Loop**

The HCMD loop is the core of the discipline.

1. **Task**  
   A concrete, bounded objective.

2. **Initial Answer**  
   Imperfect by design. It exposes structure.

3. **Refinement**  
   Identify what is unclear, missing, or structurally weak.

4. **Clarification**  
   Rewrite the task or the structure to remove ambiguity.

5. **Iteration**  
   Repeat until the structure is minimal and coherent.

The loop is not a technique.  
It is a discipline of attention.

---

## **4. Key Artifacts in HCMD Tutorials**

HCMD tutorials use a small set of artifacts. Each has a precise role.

### **4.1 STS (Structured Task Specification)**  
A minimal, unambiguous description of the task.  
It defines *what* must be done, not *how* to do it.

### **4.2 Refinement Notes**  
Short, structural observations about what is unclear or incomplete.  
They guide the next iteration.

### **4.3 Implementation**  
A concrete realization of the STS.  
Different languages may be used to expose different structural properties.

### **4.4 LOG**  
A behind‑the‑scenes record of decisions, corrections, and structural insights.  
It is not a diary.  
It is a structural audit trail.

### **4.5 Understanding the Loop**  
A reflective summary of what the loop revealed.  
It is not a conclusion.  
It is a structural consolidation.

---

## **5. Roles in the Tutorial**

### **5.1 The Reader**  
The reader performs the loop.  
The tutorial is a scaffold, not an authority.

### **5.2 Copilot**  
Copilot is a collaborator.  
It provides structure, refinement, and implementation support.  
It does not replace the reader’s judgment.

### **5.3 The Discipline**  
HCMD itself is the governing structure.  
Both reader and Copilot operate within it.

---

## **6. How to Read an HCMD Tutorial**

### **6.1 Read for Structure, Not Answers**  
The value is in the refinement, not the final code.

### **6.2 Follow the Loop**  
Observe how each artifact leads to the next.  
The sequence is intentional.

### **6.3 Reproduce the Steps**  
Do not skip the initial imperfect answer.  
It is essential to the discipline.

### **6.4 Compare Your Loop to the Tutorial’s Loop**  
Differences reveal your own structural habits.

### **6.5 Treat the Tutorial as a Performance**  
It shows how HCMD behaves under constraints.  
It is not a template to copy.

## **8. Environment Expectations**

HCMD tutorials use minimal, standard environments:

- .NET 8 / Visual Studio 2026  
- Java (optional)  
- No interactive REPL  
- No specialized tooling  
- Everything reproducible from source  

The environment is intentionally simple.  
The complexity belongs to the structure, not the tools.

---

## **9. How to Perform the Loop Yourself**

1. Choose a task.  
2. Write an initial STS.  
3. Produce an initial answer.  
4. Identify structural weaknesses.  
5. Refine the STS.  
6. Re‑implement.  
7. Repeat until minimal.  
8. Document the LOG.  
9. Summarize what the loop revealed.

The loop ends when the structure is clear, not when the code is long.

HCMD is a discipline of clarity.  
The tutorials demonstrate the discipline in action.  
This Meta Guide provides the conceptual frame.  
The rest is practice.
