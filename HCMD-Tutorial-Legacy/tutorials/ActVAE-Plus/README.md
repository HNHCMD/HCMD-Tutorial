# ActVAEP – Advanced Variational Autoencoder Project

A Human‑Centered Meta‑Development (HCMD) re‑architecture of the major VAE variants.

ActVAEP extends the original ActVAE project by integrating the full evolution of
Variational Autoencoders into the HCMD four‑layer structure:

1. Meaning Layer  
2. STS (Structured Task Specification)  
3. PSC (Pseudo‑Structural Code)  
4. Implementation  
5. Interpretability (added for ActVAEP)

The goal is not to collect models, but to express the entire VAE family in a
single, coherent, human‑centered conceptual language.

## Meaning Layer (01)

Defines the conceptual purpose of each VAE variant:

- **β‑VAE** – disentanglement  
- **FactorVAE** – independence  
- **DIP‑VAE** – geometric alignment  
- **Hierarchical VAE** – multi‑level meaning  
- **Flow‑VAE** – flexible latent geometry  
- **Causal VAE** – causal factors and interventions  

This layer answers:  
**“Why does this variant exist?”**

---

## STS – Structured Task Specification (02)

Defines *what must be done* for each variant in deterministic, implementation‑free tasks.

Examples:

- ApplyBetaScalingToKL  
- TrainLatentDiscriminator  
- ComputeLatentCovariance  
- EncodeGlobalLatent  
- ApplyFlowTransformToLatent  
- PerformLatentIntervention  

This layer answers:  
**“What tasks define this model?”**

---

## PSC – Pseudo‑Structural Code (03)

Defines the structural modules and flows for each variant.

Examples:

- `BetaScaler`  
- `LatentDiscriminator`  
- `CovarianceDeviation`  
- `GlobalEncoder` / `LocalEncoder`  
- `FlowTransform`  
- `CausalGraph`  

This layer answers:  
**“How is the system organized?”**

---

## Implementation (04)

Minimal, structural code patterns that directly reflect the PSC.

Includes:

- β‑VAE KL scaling  
- FactorVAE adversarial loop  
- DIP‑VAE covariance penalty  
- Hierarchical VAE multi‑level KL  
- Flow‑VAE invertible transforms  
- Causal VAE counterfactual generation  

This layer answers:  
**“How does the structure become code?”**

---

## Interpretability (05)

A unified interpretability framework across all variants:

- axis‑aligned meaning (β‑VAE)  
- independence (FactorVAE)  
- geometric clarity (DIP‑VAE)  
- global/local separation (Hierarchical VAE)  
- flexible geometry (Flow‑VAE)  
- causal interventions (Causal VAE)  

This layer answers:  
**“How do humans understand the model?”**

## Purpose of ActVAEP

ActVAEP is a **conceptual unification** of the VAE universe.  
It provides:

- a single language for all variants  
- deterministic task structure  
- modular architecture  
- minimal implementation  
- complete interpretability  

ActVAEP is designed for clarity, responsibility, and human‑centered reasoning.

---

## HCMD Philosophy

ActVAEP follows the HCMD principle:

**Meaning → STS → PSC → Implementation → Interpretability**

This creates a stable, expandable conceptual village where new models can be
added without breaking the architecture.
